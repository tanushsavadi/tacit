# User evaluation status and procedure

No human effort or clinical effectiveness result was collected. No real AAC-user study, consenting teammate interview, blinded expected-answer labels, keystroke timing or listener-confirmed sentence exists. Automated scripts are engineering checks, not usability participants.

Use EVALUATION_PLAN's A (ordinary TACIT), B (manual-context Help Me Respond), C (Flow) comparison on counterbalanced unseen scenarios. Let the participant state intended meaning privately to an evaluator; do not let Gemini judge its own equivalence. Include intentional disagreement, answering an older question, changed conditions, interruptions, two simultaneous drafts and a correction to the correction. Record physical actions, keystrokes, time to correct explicit response, lost drafts, resume time, false/missed prompts, mental effort and TACIT-caused interruptions. Report errors even when the user approved them.

Do not assume a nonspeaking participant has difficulty understanding language. Ask how they prefer to access/author/control messages. Include motor, hearing, language and visual access choices; preserve camera-free manual communication. Start with consenting nonsensitive teammate feasibility trials; later AAC-user co-design/study needs its own consent, accessible procedures and fair compensation. Prototype thresholds do not validate automatic speech or general medical benefit.

The most informative next comparison is not another scheduling referent chip. Test whether a user returns to an unfinished thought faster and notices a genuinely relevant changed condition without extra false alerts. If the deterministic store/templates provide equal benefit, keep those and reject unnecessary model calls.
